# scripts/loop: the delivery loop (brother.loop)

- The chain: `scripts/loop/loop_until.sh` (deadline, stop codes 42 to 46) runs `scripts/loop/loop_pass.sh`, which lands (`scripts/loop/land_batch.py --push`), closes (`land_batch.py --close`, the frozen closer calling `scripts/close_unit.py`) and admits (`scripts/loop/runner_pool.py`, one `scripts/loop/unit_runner.py` process per admitted sub unit). Facts with line numbers: the loop trace of 2026-10-30 under the hub's docs/plan/runs folder (a hub record, not shipped).
- State owners, never shadowed: `scripts/loop/plan_store.py` writes the plan under its lock; `scripts/loop/unit_ledger.py` the grades; `scripts/loop/stage_log.py` the stage rows; `scripts/loop/breaker.py` the transport breakers; `scripts/loop/diag_notes.py` and `scripts/failure_ledger.py` the lessons a brief reads.
- Who runs: the DEPLOYED copies in the maintainer's own bin folder outside the repository, staged by `scripts/loop/deploy_stamped.py` from a frozen revision, not this checkout. A change here reaches the loop only through a landing that redeploys; a loop tool change is HELD before its push by `land_batch.py`.
- Nearest checks, run after the edit: `python3 -B scripts/test_loop_wiring.py --max 4`, `python3 -B scripts/loop/test_secret_scan.py`, `python3 -B scripts/test_loop_lifecycle_probes.py`, `python3 -B scripts/test_loop_tool_parity.py`, and the suite beside the file you touched (`test_<name>.py` here or in `scripts/`). The whole gate at the integration boundary.
- Admission facts that bite: `--dry` is not write free; `BROTHER_WIP_GATE` defaults to report; `room for 0` names no limiting input until LOOP1.a lands; `lane` and `loop_gradable` are read by nothing until LOOP1.b lands.
- Escalate to host proof when a hook, a seat or a login path changes (`scripts/loop/native_worker.py`, `scripts/loop/brother_login.py`): the HP1 suites `scripts/test_host_live_proof.py`, `scripts/test_host_live_verify.py`, `scripts/test_host_live_claude.py`, and a signed in recording the owner makes.
- Model and effort: `scripts/loop/model_router.py` picks the model from the registry it finds (the hub's docs/plan/model-registry.json, else ~/.claude/model-registry.json, else it refuses; the registry is not shipped); the effort is the adapter's floor or higher (`scripts/loop/model_call.py`, the bridge at xhigh); record the effective pair in the ledger row, never the requested label.

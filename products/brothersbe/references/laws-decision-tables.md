### L12. A recommendation with no evidence is NO-DATA
WHEN: a decision table is consulted. One table ships, the architecture shape table; integration, storage, consistency and failover are human review until their tables land with fixtures.
INPUTS: the `shape` table in `tables/architecture.json` and the context values supplied by the operator.
RULE: if no criterion contributed (empty context, or every value matched nothing), the verdict is NO-DATA and the recommendation and alternatives are suppressed rather than shown. A value matching none of a criterion's known keys, or a number falling outside every range the criterion scores, is reported as unrecognized, so a typo is distinguishable from an omission. The number case was silently dropped: `deploying_teams=0` produced "no criterion was answered" over a run that answered one, and beside a second criterion it produced a confident recommendation with nothing saying half the input had been discarded, while the type error one line above it was reported. Every non-NO-DATA output carries its deciding criteria, its flip condition, the falsification tier the recommendation rests on (a deterministic check, then a mutation calibration, then a fresh-context refute, with reasoning alone read as NO-DATA rather than a tier), and an explicit option to return control to the developer instead of accepting the recommendation, and the flip condition belongs to the RECOMMENDATION rather than to the table. One string served the whole table, so a run recommending `services` off nine deploying teams and high failure isolation was handed a flip condition naming two conditions that were already true. A flip condition already satisfied can never fire, which makes it decoration in the one law that promises it. One limit remains and is stated rather than dressed up: the flip line belongs to the recommendation, not to the RUN, and nothing evaluates it against the answers that produced it, so a run at three deploying teams can still be handed a line that says to revisit below four. Reading the flip line against your own answers is yours to do. An exact tie between options is disclosed with the raw scores rather than broken in silence, and a vote for an option the table does not declare is reported as unrecognized rather than silently discarded.
OUTPUT: proceed with the recommendation and its flip condition, or stop and ask (NO-DATA).
ENFORCED BY: `tools/sbe_decide.py` (recommend), fixtures in `evals/run_evals.py`. Asking for a table that does not exist names the tables that do and exits nonzero, so a missing family reads as human review rather than as a broken tool.

# Bypass coverage

An external review listed 35 ways a person or an agent could get past these
controls. This table says, for each one, whether a fixture proves the control
catches it, whether it cannot be exercised on a developer laptop at all, or
whether nothing here catches it yet. Every row is exactly one of three:

- **COVERED**: a fixture exists and is named. Break the control it targets and
  that fixture goes red.
- **UNREACHABLE HERE**: it cannot be exercised with no network, no GitHub
  credentials, no warehouse and no second estate. The row names what is missing.
- **UNCOVERED**: nothing catches it today. The row names what covering it would
  take. Some UNCOVERED rows carry a LIMIT fixture: a test that pins the bypass
  WORKING, so the hole is a decision somebody made rather than a surprise
  somebody finds. A limit fixture is not coverage and never makes a row COVERED.

Totals: 19 COVERED (13 by suites that already existed, 5 by
`tools/test_sbe_bypass.py`, 1 by BR-1014's Bash and Stop write boundary),
6 UNREACHABLE HERE, 10 UNCOVERED.

Read the totals the way this project reads a verdict: a green run of
`python3 tools/test_sbe_bypass.py` means the rows that suite owns were tested. It
says nothing about the UNREACHABLE HERE and UNCOVERED rows, and nothing about the
COVERED rows other suites own.

## How the fixtures were calibrated

A fixture nobody has seen fail proves nothing. Every fixture in
`tools/test_sbe_bypass.py` was calibrated the same way: break the control it
targets in the tool, confirm the fixture goes red, restore the tool, confirm it
goes green. Twenty one breaks were applied, one per fixture, and all twenty one
turned the target fixture red. Examples of what was broken: the review-id branch
made to return PASS, `git log -1` widened to `-3` so an earlier commit's trailer
carried forward, the row-count comparison made to refuse an empty restore, the
scope note made to count silent directories without naming them, the fence
hook's `realpath` reduced to `abspath`, `one_line` made a pass-through, and the
receipt's covered-file check made to return nothing.

The LIMIT fixtures were calibrated the same way, against the opposite change:
they go red when the tool gets BETTER (when aliases start being folded, when an
exemption starts reading an expiry date, when a PASS sentence starts claiming a
snapshot resolved). That is what makes them a tripwire on the table rather than
a comment. Row 21's case-variant fixture used to be an example of exactly this:
it went red the moment `tools/sbe_fence_hook.py` learned to case-fold a missed
comparison, which is why it moved from a LIMIT fixture to a COVERAGE fixture
here instead of staying a comment about a hole nobody closed.

## Reading this table with the rest of the docs

`docs/KNOWN-LIMITS.md` states the limits this project ships with, in prose, and
points here. `docs/THREAT_MODEL.md` states who this defends against.
`INVARIANTS.md` states what must stay true. Where any of them disagrees with a
fixture, the fixture is right and the prose is stale.

## Post-audit: one scenario closed since the review

The 35 rows above are the audit as reviewed, and stay numbered exactly as
reviewed. One more scenario changed status the same night, and gets a note
here instead of a row number.

- **Scenario**: a secret typed on the command line reaching the receipt (the
  argv path, distinct from the stdout and stderr paths row 5 already covers).
- **Status**: COVERED, as of tonight.
- **Proof**: `tools/test_sbe_evidence.py::test_a_secret_shaped_argv_token_is_redacted_not_recorded_verbatim`.
  `redact_argv()` masks any token matching a shape `tools/sbe_telemetry.py`'s
  own `SECRET_PATTERNS` already knows, before the receipt is written. The
  marker design carries its own proof: it writes `[REDACTED:<shape>]`, naming
  which pattern matched, rather than a bare `[REDACTED]` that would hide
  whether the right thing fired.
- **Residual**: `SECRET_PATTERNS` is a finite, fixed list. A secret shaped like
  nothing on that list still reaches the receipt verbatim, the same residual
  every pattern-matched control on this page carries.

A future re-audit is the right place to fold this into the table proper with
its own row number; until then it stays here so the 35 above stay exactly what
was reviewed.

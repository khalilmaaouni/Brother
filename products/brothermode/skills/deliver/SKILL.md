Plugin root: a Claude Code install exports `${CLAUDE_PLUGIN_ROOT}` and a Codex install exports `${BROTHER_PLUGIN_ROOT}`; both name this plugin's own directory, so read whichever variable appears below as the one your client set. On a clone install neither is set: run the same commands from the checkout root instead.

Outcome to produce: one delivery packet the user can read, share, and act on, proving what was built and how it was checked.

Enter the delivery flow of the brotherme skill. Run the mechanical command `python3 "${CLAUDE_PLUGIN_ROOT}/tools/brothermode_cli.py" deliver` (the packaged console script is `brothermode deliver`) to generate the delivery packet from that project's own records; never fill DELIVERY-PACKET.md by hand and never answer from memory of this conversation about what is done. A plugin install exports `${CLAUDE_PLUGIN_ROOT}` for skill and command content, so that path resolves on its own; on a clone install, where the variable is unset, run `python3 tools/brothermode_cli.py deliver` instead, from the BrotherMode root (the directory that holds `tools/`). Either way, run it from the user's project folder so it reads and writes that project's own records. Do not say "ready to deliver" unless a verifying check ran after the last edit and passed; if any check is missing or failing, say so plainly and list what remains instead of delivering.

The grounding gate, when this project has an outcome contract (the record `adopt` or the intake screen wrote under `docs/decisions/inflight/`). Before you run deliver, write an answer file: one JSON object holding `language` (the language the person asked in), `answers` (one entry per must-answer field of the contract, each with `field`, `text`, and a `receipt_id` naming a receipt the contract already carries), and a short `summary`. Then pass it: `deliver --project-id ID --contract docs/decisions/inflight/<record>.json --answer-file answers.json` (the contract is found on its own when exactly one record sits in that directory). Deliver refuses, before it writes anything, when the answer file is in a different language from the ask, when a must-answer field has no entry or an empty one, or when a citation names a receipt that does not exist or that came back FAIL or NO-DATA: a must-answer field is grounded only by a PASS receipt, or by a research citation, which is a `receipt_id` beginning `research:` whose answer text carries a line starting `Source:`. Write the answers in the user's own language, one per must-answer field, each citing the receipt that backs it; never write a field from memory of this conversation. When the gate passes, deliver writes the packet with a Grounding line and marks the contract delivered.

Continuity, before you end the session. Delivering a packet is not the same as finishing the work. If open work remains after this delivery, run `python3 "${CLAUDE_PLUGIN_ROOT}/tools/brothermode_cli.py" continue` (the packaged console script is `brothermode continue`; on a clone install run `python3 tools/brothermode_cli.py continue` from the BrotherMode root). It writes the handoff packet from that project's own records, prints the exact command that starts the next session, and starts it. Add `--dry-run` to write the packet and print the command without launching anything, which is how you rehearse a handover you are not ready to trigger. If the launch is refused or impossible, say so plainly and name the packet file the next session must read: Silence is the only forbidden outcome.

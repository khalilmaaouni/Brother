# Review a Brother receipt

## 1. Start with changed files

Every changed file should map to bounded work/evidence. Surprise files are review-first.

## 2. Read the exact check

Would it fail if the relevant behavior were absent? A broad suite can be useful while still not discriminating this change.

## 3. Look for discrimination

Pre-change failure, reversion/mutation, or an independent oracle makes a stronger link between claim and evidence.

## 4. Inspect independence

If the same model wrote code and check, decide whether the risk requires a separate contract, human-specified oracle, differential check, or independent review.

## 5. Resolve material NO-DATA

Gather evidence, narrow the claim, or explicitly accept the uncertainty as a human decision.

## 6. Separate acceptance from release

Accepting delivery does not automatically mean publishing/deploying it.

## Verify the result

You can explain the evidence chain without relying on the agent's summary prose.

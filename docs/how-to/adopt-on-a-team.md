# Adopt Brother on a team

## Agree on authority first

Name who can accept delivery, merge, release, override a safety gate, and accept material NO-DATA. Brother reflects authority; it does not invent it.

## Start with one expensive evidence problem

Migrations, production incident fixes, sensitive backend changes, data reconciliations, or release readiness are better pilots than mandating Brother for every typo.

## Define minimum evidence

Agree on invariants, independent oracles when required, recovery evidence, environment/data identity, receipt retention, and human decision points.

## Configure scope and Vault deliberately

Set repository hook scope and memory policy before broad distribution.

## Preserve existing tools

Detect/reuse the team's pytest, dbt, Terraform, Kubernetes, CI, warehouse, BI, QA, and observability tooling. Do not create dependencies merely to make a Brother-branded workflow.

## Measure outcomes

Look for less review reconstruction, fewer repeated failures/escaped defects, and clearer handoffs. Do not optimize number of generated tests or Brother invocations.

## Verify the result

Pilot with real senior reviewers and revise the practice pack based on what they still had to reconstruct manually.

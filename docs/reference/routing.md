# Routing reference

Brother has one user door. The user describes the work, not an internal product.

## Decision order

The installed `using-brother` skill is the current routing authority.

### Bare invocation

1. If unfinished Brother work exists for the repository, discover it and offer/resume it by plain-language outcome.
2. If none exists, ask one question: what are you trying to do?

Do not present a product menu.

### Explicit work

| Work shape | Route |
| --- | --- |
| Trivial, reversible, nobody would ask for evidence later | No Brother trust ceremony. |
| Substantial change another person will later trust | Execution provenance. |
| Money, contracts, customer/personal data, auth, migration, production path, or decision-grade figure | Change assurance; missing evidence is `NO-DATA`. |
| Decision-grade claim scoring against later reality | Experimental claim-verification boundary unless the release says otherwise. |

## Router boundaries

The router owns no second task registry, no second file-ownership truth, no PASS/FAIL/NO-DATA calculation, no release decision, no default-branch merge, no assurance arithmetic, no claim scoring, and no product-choice menu.

## Resume

Continue/resume are discovery operations. When one clear unfinished outcome exists, users should not need a run directory or opaque id.

## Authority

Primary: `bundle/skills/using-brother/SKILL.md`.

Deeper boundary/handback rules: `bundle/skills/using-brother/references/router-details.md`.

# State and file locations

## Target repository

Keep product source and deliberate Brother configuration there. Do not put plan/run artifacts in the target repo when the engine requires a clean baseline. Repository-local hook configuration may use `.brother/config`.

## Run store

Run state and receipts belong in a durable host-specific Brother run root outside the target source tree. Exact defaults differ by host/install path; prefer installed runtime paths over copied home-directory examples.

## Decision records

Intake tooling may create `docs/decisions/` records in the Brother estate. These are data, not guaranteed public pages.

## Schema

Outcome contract: `docs/schema/outcome-contract-v1.json`.

## Generated inventory

`SYSTEM.md` is generated by `scripts/system_doc.py`; never hand-edit it.

## Historical evidence

`docs/releases/**` and `docs/deliveries/**` are evidence/history, not prose-cleanup targets.

# Professional practice packs

Brother should understand professions without turning them into modes.

A senior data engineer and senior backend engineer may both “change a schema,” but meaningful evidence differs. Data engineering may require lineage, late-arrival handling, backfill idempotency, reconciliation, semantic contracts, and cost. Backend engineering may require API compatibility, transaction boundaries, retry semantics, concurrency, and rollback.

A professional practice pack supplies:

- common work classes;
- high-cost failure modes;
- intake pivots;
- useful existing tools;
- evidence families;
- proven test patterns;
- Vault knowledge;
- acceptance questions.

The user still enters through one Brother door. Brother infers work/risk and composes lenses. A metric-pipeline change can need data engineering, analytics semantics, BA traceability, and QA oracle discipline at once.

The pages under `docs/personas/` are the public application layer for this idea. They do not imply the current outcome-contract schema accepts eleven profession values.

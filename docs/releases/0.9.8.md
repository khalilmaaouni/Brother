## What changed

The one repo cutover (M6 of docs/plan/ONE-REPO-TRANSITION-2026-08-31.md).
BrotherMode and BrotherSBE now ship FROM this same repository, at
`products/brothermode` and `products/brothersbe`, instead of from their own
separate repositories. The marketplace re-points both plugins to a
`git-subdir` source rooted at this repository and this same tag; only the
bundle plugin's own source (`./bundle`) is unchanged, because it already
lived here.

Nothing about how a user installs Brother changes:

    claude plugin marketplace add https://github.com/khalilmaaouni/Brother.git && claude plugin install brother@brother

An engineer who installs `brothermode` or `brothersbe` directly, rather than
through the bundle, now resolves to this repository's `products/` subtree at
this tag instead of to BrotherModeUp or BrotherSBE. The commands, skills, and
hooks each plugin ships are unchanged; only where they are fetched from
changed.

The public repository's own `PROJECT.md` now describes the public repository
truthfully (the exported file is a distinct, public-true variant of the
private hub's own orientation file; see `scripts/export_public.py`'s
`EXPORT_OVERRIDES`), and names the one check a clone of this tree can
actually run: `sh scripts/bundle-install-smoke.sh`. It no longer names the
private hub's own internal battery, which was never runnable from a public
clone.

## What an installed user experiences

Nothing, except one home. The install command is identical, the plugin
names are identical, the versions BrotherMode (3.4.2) and BrotherSBE (3.7.0)
ship are identical. The only externally visible change is that `git clone`
of `khalilmaaouni/BrotherModeUp` or `khalilmaaouni/BrotherSBE` now points at
a repository that is retiring (see
`docs/plan/m6-successor-pointers/`): the same code and history lives on at
`khalilmaaouni/Brother`, under `products/`.

## Known limits, declared

The public repository does not carry tag `v0.9.8` until this release is
actually cut and pushed by the integrator; `scripts/release_invariant.py`
correctly FAILs on that link until then, and that FAIL is expected and
disclosed rather than worked around. The `docs/` subdirectories of both
products (handover packs, closure records, dossiers, session-dated research)
are not exported; only a hand-picked set of top-level reference docs per
product ships publicly today, named in `docs/plan/EXPORT-ALLOWLIST.txt`.
`products/brotherds` ships nowhere yet: it is not an installable plugin and
its own `PROJECT.md` says nothing is built.

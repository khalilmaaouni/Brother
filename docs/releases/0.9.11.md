# Brother 0.9.11

## Source revision

Published as tag v0.9.11 on github.com/khalilmaaouni/Brother; that tag is the public hash of this cut. The hub commit it was cut from was not recorded at the time, so this note carries no private-record hash.

## What this release carries

Crash recovery stops finishing nothing. The resolver added in the previous cut
asked git whether the lane was an ancestor of canonical, which is trivially
true for a lane branch created at canonical's tip before its worker has
committed anything. A resume landing in that window reported the unit as
already integrated when nobody had integrated it: no worker dispatched, no
evidence recorded, and every retry hitting the same short circuit until the
budget was gone. The question asked is now the one that was meant: because
integration always merges with no fast forward, a real integration leaves a
merge commit whose second parent is the lane tip, so asking whether the lane
tip is anybody's parent separates a lane that committed nothing from a lane
merged long ago. Proven by scripts/test_integrate.py, whose empty-lane case was
driven backwards against the broken version first.

Autonomous integration gains a brake. A stop file refuses the merge before the
tree is touched, so a run can be halted without racing a half-applied merge,
and the bridge no longer releases a resumed unit as failed when the record says
it was already integrated. Driven both ways in scripts/test_integrate.py.

Also in this cut, from the run 5 gauntlet fixes: the engine's exit code derives
from the verifier's own stamp rather than from claim state, the bridge
recognises a real versioned install and treats resolution as loading, and a
proof command that reads nothing composes as NO-DATA instead of adding up to a
pass.

Both products move with their content. BrotherSBE 3.7.3 takes its eval suite to
547 of 547 for the first time (seven regressions were one input-contract change
wearing seven faces) and its silent-failure lint to PASS. BrotherModeUp 3.4.4
fixes vault link expansion, which resolved 178 of 855 eligible link targets and
now resolves all of them, closes 273 silent-failure lint sites across 97 files,
and repairs a release defect from the previous cut where the 0.9.10 bump missed
pyproject.toml. The marketplace pins both products to this release's tag.

## The declared exception this release clears

The battery carried release-invariant as an expected failure from 2026-09-01,
recorded because runtime content had moved past tag v0.9.10 while the version
string stood still, which is exactly the state that invariant exists to name.
The exception said it would be removed when v0.9.11 was bumped, exported and
tagged. It is removed in this change, and release-invariant decides that for
itself rather than being told.

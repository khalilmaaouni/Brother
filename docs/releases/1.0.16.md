# Brother 1.0.16

## Source revision

Cut from commit `e8321b6f97037e1ab8dc797d3fd28ffd841cab70` on this repository.

The export manifest (the exported file list with each file's sha256) and the
tree-reproduction check are stamped at publish time, when the release is
tagged. To verify a published tree once the tag exists:

    python3 scripts/reproduce_export.py --verify-tree --tag v1.0.16

## Changes

Closes a learning-loop failure mode: the attempt breaker now runs its own
research in-process and folds the real result into a refusal, instead of only
naming a command for someone to run by hand (mode LM3). A recorded lesson is
no longer truncated at 200 characters when it is surfaced at the moment of
action, so its full remedy shows (a measured cause of repeated mistakes).

Hardens the run cancellation path's own regression test so it proves the
worker reaper rather than a retry backoff, and makes the retry backoff base
tunable for tests without changing the production default.

Documentation now includes a host-neutral token-optimization playbook in
`docs/how-to/token-optimization.md`. It names the six levers, explains the
cache-aware cost model, records the anti-pattern ledger, and adds Brother's
inline-first swarm and subagent routing economy. The playbook also describes a
future human-gated learning loop. Its reference is the public
`github.com/khalilmaaouni/token-shield` repository.

The Vault guide in `docs/how-to/use-the-vault.md` now documents root selection,
retrieval signals, point-of-action recall, privacy boundaries and persona
patterns. A new `docs/how-to/use-brotherds.md` guide explains the BrotherDS
claim path, receipts, gates, outcomes, persona problems and its boundary with
the other products. Both guides include Mermaid schematics and links to the
authoritative reference pages.

The release also fixes the LM3 learning loop: the attempt breaker runs
`find_out` in-process and folds the real result into its refusal. A surfaced
lesson's remedy is no longer truncated at 200 characters. The Area 5
run-cancellation regression test now proves the worker reaper, while the retry
backoff base is tunable in tests without changing the production default.

Finally, the CI self-firing fix changes `required-fast.yml` to
`workflow_dispatch` and removes the ruleset requirement for that check. This
keeps verification explicit and prevents the workflow from firing itself.

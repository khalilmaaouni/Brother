# Brother 0.9.6

## What changed for developers

A crashed run resumes by its plain outcome name on a bare invocation: run
`brother_run --continue` with no argument and it matches the crashed run
back to the one outcome record in the repo, rather than asking you to
remember or retype an identifier.

A dead process's lock releases in seconds, not twenty minutes: the claim
store now checks whether the process that took a claim is still alive
(PID liveness) and reclaims a claim left behind by a killed process
immediately, instead of waiting out a long stale-claim timeout.

## Reliability fixes

Concurrency tests now pin their own slot count instead of borrowing
whatever the host machine happens to have free, so a test's pass or fail
no longer depends on how busy the machine running it is.

The private-terms scanner enforces a word boundary before matching a
lowercase name, so it no longer flags an ordinary word that merely
contains a watched name as a substring.

## Crash/recovery

The claim store reclaims a claim by checking the owning process's PID for
liveness rather than trusting a stale timestamp alone. The reclaim only
fires when the claim's own recorded hostname matches the current host, a
cross machine guard that stops one machine from reclaiming a claim that a
different machine is still legitimately holding, even if the recording
machine's clock or process table cannot be checked from here.

## Install/update

    claude plugin update brother

## Known limits

The cross machine hostname guard is unit tested only; it has not yet been
proven end to end across two real machines racing for the same claim.

The area 9 self rig redesign is open: area 9 of the eleven capability
areas still needs its acceptance harness rebuilt, tracked as a known gap
in the readiness roadmap, not shipped in this release.

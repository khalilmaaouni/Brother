## What this release carries

Drafted by Codex exec on 2026-09-08 at 08:1x JST, log docs/plan/runs/night-2026-09-07/codex-note-1.0.11.log, verified against the tree by the cutting session.
Brother 1.0.11 is a plain release: it carries the P0 vault verification floor, P1 managed-run safety, P3 governed landing, and P4 critical evidence closeout, plus the FAST-0 eligibility and escalation contract. The final tree fast gate reads 17 of 17, and its full battery reads 229 pass, 14 fail, 3 no-data: 13 inherited battery reds are untouched, and the one new red is the declared release invariant until this cut. Critical closeout now declares 17 capabilities, with 6 runner checks and 11 labeled self-test-only. It also ships test_all.py beside bm_fence_hook.py, so enforced mode no longer refuses every tool write when that file is absent, and names the missing file when it is missing. This release does not wire FAST-0 into brother_run.py, add a --fast switch, or measure its benchmark; it does not turn the 11 self-test-only critical capabilities into independent proof; and it does not fix the 13 inherited battery reds.

Every delivery report ends with one receipt sentence per unit, the acceptance screen line and, where a risk class was named, the release screen line, and the scoping sentence `exit 0 means no check failed. It does not mean everything is proven: only the checks named above ran, and a check nobody wrote cannot fail.` Proven by `python3 scripts/test_receipt_door.py` at 153 OK.

Each wait during a run prints one governor line when it starts and one when it ends, never once per poll. Proven by `python3 scripts/test_brother_run.py` at 228 OK.

The recall hook prints `Recalled N lesson(s) from the Vault for <file>` before an edit of a file the Vault knows. It prints nothing on a genuine no-match, and writes nothing before consent. Proven by `python3 products/brothermode/tools/test_vault_recall_hook.py` at 31 OK.

Vault promotion enforces separation of duties. `SEPARATION_OF_DUTIES_ENFORCED` is `True`, and an author cannot approve the same candidate: flipping the flag turns `test_the_default_policy_is_on_the_same_actor_is_refused` and `test_the_same_actor_with_no_enforce_argument_is_refused_by_default` red. Proven by `python3 products/brothermode/tools/test_bm_vault_lifecycle.py` at 42 OK.

The promote command and the approval pane apply the same rule, proven by `python3 products/brothermode/tools/test_bm_vault_promotions.py` at 23 OK and `python3 products/brothermode/tools/test_bm_vault_pane.py` at 12 OK.

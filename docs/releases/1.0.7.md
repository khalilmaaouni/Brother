## What this release carries

This cut supersedes 1.0.6 for one reason: the signed-in Codex proof of 1.0.6 (row X8, 2026-09-05 18:02 JST) produced no file change. Inside a `codex exec` turn the engine's per-unit worker cannot call any model, so it changed nothing, and the unit's done check (`python3 -m unittest`) already passed on the untouched toy, so the unit read integrated with an empty scope and a NO-DATA receipt. Three rules now sit in the Codex skill (`bundle/skills/using-brother/SKILL.md`, generated into `bundle/codex-skills/`) and in `docs/codex/SMOKE-RUNBOOK.md` step 6: every done check must fail on the untouched tree before the engine runs; under Codex the agent supplies both seams from the start, `DOOR_MODEL_CMD` for the plan and `MODEL_WORKER_CMD` for the change, and the engine still isolates, checks, audits scope and writes the receipt; and a NO-DATA receipt from a pre-green check is the agent's own defect to fix in the same turn, never a forcing condition to ask about. The exact signed-in shape is now a regression that needs no Codex binary: a pre-green check with a worker that changes nothing must read exit 2, `check_passed_before` true and no changed file, and a red check with an applying worker must read exit 0 with two changed files and evidence. Proven by `python3 scripts/test_codex_smoke.py` at 25 OK. The pre-pass rule and the receipt requirement are unchanged.

Every delivery report ends with one receipt sentence per unit, the acceptance screen line and, where a risk class was named, the release screen line, and the scoping sentence `exit 0 means no check failed. It does not mean everything is proven: only the checks named above ran, and a check nobody wrote cannot fail.` Proven by `python3 scripts/test_receipt_door.py` at 150 OK.

Each wait during a run prints one governor line when it starts and one when it ends, never once per poll. Proven by `python3 scripts/test_brother_run.py` at 210 OK.

The recall hook prints `Recalled N lesson(s) from the Vault for <file>` before an edit of a file the Vault knows. It prints nothing on a genuine no-match, and writes nothing before consent. Proven by `python3 products/brothermode/tools/test_vault_recall_hook.py` at 27 OK.

Vault promotion enforces separation of duties. `SEPARATION_OF_DUTIES_ENFORCED` is `True`, and an author cannot approve the same candidate: flipping the flag turns `test_the_default_policy_is_on_the_same_actor_is_refused` and `test_the_same_actor_with_no_enforce_argument_is_refused_by_default` red. Proven by `python3 products/brothermode/tools/test_bm_vault_lifecycle.py` at 39 OK.

The promote command and the approval pane apply the same rule, proven by `python3 products/brothermode/tools/test_bm_vault_promotions.py` at 23 OK and `python3 products/brothermode/tools/test_bm_vault_pane.py` at 12 OK.

The 15 legacy command shims remain in this cut, per decision D2.

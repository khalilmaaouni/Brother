## What this release carries

This release carries the Codex package: `bundle/.codex-plugin/plugin.json` beside the
Claude manifest, the generated `bundle/codex-skills/` tree, the hooks adapter
`scripts/codex_hooks_install.py`, and the operator runbook `docs/codex/SMOKE-RUNBOOK.md`
with `docs/codex/HOOKS-MAPPING.md` and `docs/codex/PACKAGE-SHAPE.md` beside it. The
credential free half of the smoke test is recorded under row C7 of the readiness roadmap:
`python3 scripts/codex_smoke.py` exited 0 against a real `codex` binary in an isolated home,
installing the marketplace and the plugin and reporting all 18 hooks trusted and enabled.

This release does NOT claim Codex compatibility. The credentialled half, one real Codex task
run end to end on an authenticated account, is row C7 of the readiness roadmap and is still
pending the founder's own run: the last attempt ended at `ERROR: unexpected status 401
Unauthorized: Missing bearer or basic authentication in header`. Until that run is recorded,
what ships here is the package and its shape, not a proven compatibility claim, and a reader
should treat Codex support as untested on their machine until they run the runbook themselves.

Every delivery report ends with one receipt sentence per unit, the acceptance screen line and, where a risk class was named, the release screen line, and the scoping sentence `exit 0 means no check failed. It does not mean everything is proven: only the checks named above ran, and a check nobody wrote cannot fail.` Proven by `python3 scripts/test_receipt_door.py` at 135 OK.

Each wait during a run prints one governor line when it starts and one when it ends, never once per poll. Proven by `python3 scripts/test_brother_run.py` at 188 OK.

The recall hook prints `Recalled N lesson(s) from the Vault for <file>` before an edit of a file the Vault knows. It prints nothing on a genuine no-match, and writes nothing before consent. Proven by `python3 products/brothermode/tools/test_vault_recall_hook.py` at 27 OK.

Vault promotion enforces separation of duties. `SEPARATION_OF_DUTIES_ENFORCED` is `True`, and an author cannot approve the same candidate: flipping the flag turns `test_the_default_policy_is_on_the_same_actor_is_refused` and `test_the_same_actor_with_no_enforce_argument_is_refused_by_default` red. Proven by `python3 products/brothermode/tools/test_bm_vault_lifecycle.py` at 39 OK.

The promote command and the approval pane apply the same rule, proven by `python3 products/brothermode/tools/test_bm_vault_promotions.py` at 23 OK and `python3 products/brothermode/tools/test_bm_vault_pane.py` at 12 OK.

The 15 legacy command shims remain in this cut, per decision D2.

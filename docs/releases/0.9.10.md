# Brother 0.9.10

## Source revision

Published as tag v0.9.10 on github.com/khalilmaaouni/Brother; that tag is the public hash of this cut. The hub commit it was cut from was not recorded at the time, so this note carries no private-record hash.

## What this release carries

The receipt door: every delivery now ends with its own proof in plain words.
Each delivered unit prints one sentence naming the check that ran, its captured
exit code, and where its full output lives, built from the claim store's own
re-verified evidence and never invented; a unit without a captured exit code
says NO-DATA with the reason. The engine's bookkeeping moves to the run log,
the person gets plain lines, and a completed run renders an acceptance screen
(a release screen when a risk trigger fires) that scores the evidence and poses
accept or hold as the human's question. Proven by scripts/test_receipt_door.py
(21 tests), scripts/test_brother_run.py, and the receipt-door-self line in the
battery.

Product versions move with their content: brothersbe 3.7.2 (the session cap
refusal names a file escape that works, first contact speaks the user's
language) and brothermode 3.4.3 (the ~/.claude/bm_session_cap.override escape,
proven by its own test). The marketplace pins both products to this release's
tag.

Also in this cut: the night battery's ten catches closed at cause, among them
delivery records that now carry real integration commits, decision specs whose
code anchors all resolve, and the erasure and clean-environment probes running
on ground they own.

Behind a flag, off by default: the loom. `brother_run.py --park-risky` holds
any unit whose own declared scope names irreversibility before it is claimed,
run or merged, and poses accept or hold as the person's question; the answer is
recorded with who and when, never scored, and a second answer is refused by the
filesystem. Proven by scripts/test_loom.py (25 tests, the loom-self battery
line). The default stays off per the decision of record; nothing changes for a
user who does not pass the flag.

An installed user updating from 0.9.9 sees new product versions and the receipt
sentences at their next run; nothing they depend on changes shape.

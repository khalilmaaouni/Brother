# U3: bm_store.py migration plan

Source read in full: `products/brothermode/tools/bm_store.py` (20,334 lines, SCHEMA_VERSION 22).
Core read in full: `plugin/runtime/brother/core/` (6 modules, about 120 lines of real logic).

## 0. The fact that reframes the whole unit

`bm_store.py` already exists twice, byte identical:

- `products/brothermode/tools/bm_store.py`
- `bundle/runtime/hooks/brothermode/tools/bm_store.py`

Both 20,334 lines, both sha256 `268f6783a05b...` (confirmed by direct hash, not just this claim). The bundle copy is one of 143 mirrored files, generated by `scripts/bundle_runtime.py` (its own docstring: "nothing under bundle/runtime is ever hand edited, only regenerated here"), and an installed plugin resolves it at `${CLAUDE_PLUGIN_ROOT}/runtime/hooks/brothermode/tools/`. `products/` is not shipped in an install.

So the phrase "its real module path" has no single referent. Any facade must resolve the store at runtime, not hardcode a path.

## 1. The public contract

### 1.1 Method for establishing it

Two sweeps over `products/brothermode/`: a grep for load idioms, and a frequency count of attribute accesses. The frequency counts are approximate (the regex matches any `x.name`, and test files dominate), a ranking not a measurement. The symbol lists themselves are exact, read from the file.

### 1.2 How callers reach it

Roughly 24 non-test sibling tools plus 12 test modules load it the same way: `importlib.util.spec_from_file_location("bm_store", os.path.join(HERE, "bm_store.py"))`, then `module_from_spec`, then `exec_module`. Confirmed in `bm_fence_hook.py` (line 85, spot-checked directly), `bm_bash_audit.py` (106), `bm_stall.py` (127), `bm_autosave.py` (1180), `bm_runtimes.py` (799), `bm_passport.py` (99), `bm_reconcile.py` (135), `bm_forecast.py` (104), `bm_reality.py` (106), `bm_progress_check.py` (118), and by path in `bm_project.py`, `bm_learn.py`, `bm_view.py`, `bm_lead.py`, `bm_autonomy.py`, `bm_packs.py`, `bm_handover.py`, `bm_vault.py`, `bm_docs_export.py`, `bm_visual.py`, `bm_summary.py`, `bm_sessionstart.py`, `bm_cursor.py`, `bm_threads.py`, plus `scripts/managed_safety.py`. Every docstring gives the same reason: a bare `import bm_store` would depend on whichever `sys.path` the caller happened to have.

Consequence that matters for U3: each `spec_from_file_location` call produces a separate module object. Only some callers do `sys.modules.setdefault("bm_store", mod)` afterwards. The module carries mutable module-level state:

`_FS_CASE_INSENSITIVE` (597, confirmed directly), `_FS_CASE_PROBE_CACHE` (598), `_WARNED_NO_REDACT` (1663), `_LEARNING_MOD` (5333), `_FENCE_HOOK_MOD` (5355), `_SCHEMA_MOD` (5402), `_OPEN_STORES` (7164), `_TRACK_UNCLOSED` (7179), `_UNCLOSED` (7180).

`_FS_CASE_INSENSITIVE` is the sharp one: armed one-way by `note_fs_case()` from `Store.__init__` (7214) and read by `_normcase` (646), which `paths_overlap` depends on. Two module objects in one process means two flags, and a fence that disagrees with itself about whether `API/pay.py` and `api/pay.py` are the same file. That is the H4 bypass the flag exists to close, reintroduced by duplication.

## 2. Incident to mechanism

The module docstring names five. Each maps to a different mechanism, and the mapping is not the one the U3 brief assumes.

### F1, F2, F11: two sessions each believing they held a fence over the same files

Mechanism: overlap detection, not expected_version.

- `paths_overlap(a, b)` (721), the one rule, built from `_coverage_key` (704), `_prefix_contains` (694), `_to_posix` (570) and `_normcase` (646).
- `_normcase` folds case and NFC normalizes on case insensitive filesystems, gated by a real probe: `fs_case_insensitive` (601) writes a probe file, `note_fs_case` (630) arms the sticky module flag, called from `Store.__init__` (7214). This is H4: `sys.platform` alone missed a case insensitive SMB or casefolded ext4 mount on Linux.
- `strip_worktree_segments` (925) is H1: a claim declared from inside `.claude/worktrees/x/` and one declared from the shared root now store the same logical spelling.
- `Store._find_overlap(norm_files, exclude_uuid=None)` (12256) queries every ACTIVE record's claims.
- `Store._admit(name, lifetime, norm_files, exclude_uuid=None)` (12276) is the one admission gate: `claim()` called it, resume did not, so `parked -> active` walked over another session's fence. Now called from `Store.claim` (12455) and from the `to_state == "active"` branch of `Store.transition` (12608).
- `verify(root)` (19013) re-runs the same union of claims invariant read side.

### F2, F42, the F2b class: the wrong project root

Mechanism: `resolve_root(start=None, refuse_past_git_boundary=False, env_must_contain_start=False)` (335), with `_walk_up` (319) and `require_root` (488). Order is `BROTHERMODE_ROOT`, then the nearest `.brothermode/` marker holding a store, then `.git`, never `os.getcwd()` alone. A marker anywhere up the tree beats a closer `.git`, so a vendored submodule cannot shadow a real root. Two opt-in refusals sit on top: `root-ambiguous` and `root-outside-start` under `refuse_past_git_boundary`, and the hooks' `env_must_contain_start`.

### F3: silent takeover of a name someone else was actively working under

Mechanism: session identity equality plus a partial unique index.

- The `name-active` refusal in `Store.claim` (12442), gated at 12422 on a non-empty `session_id` equal to the one on file: two CLI processes both omitting `--session` used to satisfy `("" or "") == ("" or "")` and the second silently reclaimed the first's record.
- `_default_cli_session_id()` (19640) mints a fresh per-process id so that can never recur through the CLI door.
- `CREATE UNIQUE INDEX one_active_per_name ON records(name) WHERE state='active'` (1982).
- The `not-owner` guard in `Store.transition` (12571), scoped by `_ownership_guard_applies(current_state)` (6248) to records that are currently active. The unconditional version wrongly refused a legitimate cross session resume of a parked record.
- `live-session-adopt-blocked` (12584): adopting a record active under a different live session requires explicit `adopt_from_live_session=True`, and the displacement is written into the transition note.
- The `IntegrityError` catch at 12618 turns a unique index hit during `transition` into the same `name-active` refusal.

### F13: two handovers collided on a truncated fingerprint and the second was dropped

Mechanism: full width fingerprint plus a partial unique index plus transactional atomicity.

- `Store.handover_payload(lifecycle_uuid)` (12930) computes a full 64 hex sha256 over the canonical sorted JSON of objective, files, owner, tier, check, evidence, latest digest and every decision. The earlier version truncated to 12 hex.
- `Store._insert_handover(...)` (12653), called only from inside `transition()`'s open transaction (12644).
- `handovers_undelivered_text_idx` on `(lifecycle_uuid, payload_fingerprint, heading) WHERE delivered_at IS NULL` (2730). The partial predicate matters: an index over all rows meant an acknowledged handover permanently suppressed the next one and a second park committed with no handover anywhere.
- `HandoverLost` (1599) is raised when the swallow cannot be justified by a still undelivered twin, and it aborts the whole transition: no handover, no move.

### F9: a crash truncated registry read as healthy

Mechanism: a per incident quarantine directory, a version first schema check, and write authority as a structural boundary.

- Zero byte check in `Store.__init__` (7252): sqlite accepts a zero byte file as a valid new database, so an existing one is corruption.
- `_verify_schema_or_raise(migrate=False)` (7888). Version is read first, tables second, since the original order quarantined a healthy schema 1 store opened by a schema 2 binary. Four outcomes; `schema-ahead` and `schema-behind` are `OwnershipRefused`, not `StoreCorrupt`.
- `_exec(store, sql, params)` (7118) routes every statement, so later page damage is caught on every query, not only at open.
- `_quarantine_is_warranted(cause)` (7101) fails safe: only named evidence of a damaged file moves anything. A disk I/O error or permission wall reports and touches nothing.
- `Store._quarantine_and_raise(cause)` (8103) creates `store.sqlite3.quarantine-<microsecond stamp>-<uuid8>/` with `exist_ok=False`, copies the `-wal` and `-shm` sidecars in before `close()` (a newer SQLite deletes them during close), then moves the main file, and never deletes anything.
- `ReadOnlyStore._quarantine_and_raise` (18024) overrides it to refuse without moving. The containment is structural: `ReadOnlyStore` does not inherit from `Store`, so there is no path from a diagnostic to the mover.
- `_migrate_from(from_version)` (8026) backs up through sqlite's own backup API before any DDL, runs the whole chain inside one `BEGIN EXCLUSIVE` with the version bumped last, and re-verifies from scratch afterwards.

### lifecycle_uuid and expected_version

- lifecycle_uuid: minted `uuid.uuid4().hex` in `Store.claim` (12456), permanent, never reused. `thread_dir_name(name, lifecycle_uuid)` (555) makes the on-disk working directory name change every time the identity does. `_insert_provisional_record` (10703) carries the same guarantee for provisional records.
- expected_version: the optimistic concurrency fence. Precondition at `transition` 12556, then a conditional `UPDATE ... WHERE lifecycle_uuid=? AND version=? AND state=?` at 12613 with `rowcount` checked. Same shape in `checkpoint` (12760), `decide` (12821), `mint_edit_receipt` and `edit_learning_rule`. Raises `StaleIdentity`. This closes F5/F6 (a thread kept writing into a record already closed out from under it), not the double fence class. Conflating the two is the easiest mistake to make in this migration.

## 3. Overlap with Core: precise

Core is 6 modules, about 120 lines of real logic, 51 tests, no persistence. Every function is pure except `ensure_state_layout`, which is a `makedirs`.

### 3.1 Real overlaps (four, all small, name or path collisions rather than duplicated mechanism)

Run identity. `new_run_id(prefix="br")` returns `br-YYYYMMDD-<8 hex>`, 32 bits of randomness per day. `lifecycle_uuid` is a full uuid4 hex primary key, full width because F13 was an identifier truncation collision. `controller_runs.run_id` already exists in schema 15 and is also a uuid4 hex. Core introduces a third id shape for one unit of work, and it is the weakest of the three. A real collision of responsibility, not of code.

State root. `core/state.py` `state_root(base_dir=None)` returns `os.path.join(base_dir or os.getcwd(), ".brother")`. `bm_store` uses `<root>/.brothermode/store.sqlite3` where `root` comes from `resolve_root`, whose own header says: never `os.getcwd()` alone. Two directories, two resolution rules, and Core's default is precisely the anchor F2/F42/F2b exist to forbid. `ensure_state_layout` also creates a `locks/` directory that nothing implements, next to a store whose locking is sqlite's.

Evidence. Core's `Evidence` is a frozen per-claim envelope with `ALLOWED_STATUSES = {PASS, FAIL, NO-DATA}` and `ALLOWED_DOMAINS = {mode, assurance, data, mobile, vault, core}`. `bm_store` has three different things wearing that word: the `evidence` table (schema 12, plus `criterion_id` at 20 and `origin` at 22), a per artifact row; `EVIDENCE_ORIGINS` plus `origin_satisfies()` (2958), the store's own rule for whether a row may satisfy a completion claim; and `records.evidence`, a free text column that `transition(to_state='complete')` requires non empty (12546, reason `missing-evidence`). Overlapping vocabulary, three distinct objects, zero shared code today.

Receipt and acceptance. Core's `build_receipt` is an in memory run terminal verdict dict; `record_acceptance` returns a dict and writes nothing. `bm_store` has four unrelated receipt mechanisms: `learning_approval_receipts` and `learning_state_change_receipts` (one time consent tokens, hashed nonce, 900 second TTL, fingerprint bound, consumed as the first statement of the spending transaction), `capability_receipts` (schema 20), and `autosave_receipts` (schema 1). Core's acceptance has no counterpart to `reality_records`, insert only with two `RAISE(ABORT)` triggers (3883, 3891) and an `unaccountable-acceptance` refusal (13473).

### 3.2 Genuinely different, and not covered by Core at all

This is most of the 20,334 lines, and it is the honest answer to whether Core and Mode overlap.

- Concurrent multi process ownership fencing. sqlite WAL, `BEGIN IMMEDIATE` taking the write lock up front (`Store._transaction`, 8284), optimistic concurrency by `expected_version`, `one_active_per_name`, `_admit` / `_find_overlap`, the glob coverage key semantics of `paths_overlap`, filesystem probed case and NFC folding, worktree spelling normalization. Core has no lock, no transaction, no process crossing identity and no concurrency primitive of any kind.
- Crash safety and a corruption policy. Quarantine directories, backup before migrate, 21 chained migrations (`_MIGRATIONS`, 5282), schema ahead and schema behind refusals, the read only WAL aware open ladder (`_connect_read_only`, 17825), `query_only=ON` as a second independent defence.
- Containment and privacy. `safe_project_path` path funnel, symlink and hardlink refusals, a pure Python git index and `.gitignore` parser (`_git_index_tracked_paths` 6622, `_git_ignore_decision` 6877) so the check needs no subprocess, default deny export (`export_column`, 5813), absolute path masking, the stdout/stderr/file output funnels, human block preservation.
- A 22 version schema, 40 plus tables, and about 80 named refusal reason codes that 27 plus call sites branch on.

Verdict: no meaningful duplication of mechanism. The overlap is four naming and path decisions that will collide if left unreconciled, and section 4.4 names how to reconcile them.

## 4. Recommendation

### 4.1 The recommendation

(c), a variant of (a). Build a thin adapter in `plugin/runtime/brother/mode/` that: resolves the store module at runtime from a documented, ordered location rule (not a hardcoded path); registers it under one `sys.modules` key so every caller in a process shares one module object; re-exports only the ownership contract; adds a small Core to Mode identity bridge as the only new code.

`bm_store.py` stays the sole source of truth. Nothing under `products/` or `bundle/` changes in U3. `SCHEMA_VERSION` stays 22.

### 4.2 Why not (a) exactly as worded, and why not (b)

(a) as worded fails on "its real module path": there are two, and the installed plugin loads the bundle one while `products/` does not ship. A facade hardcoding `products/brothermode/tools/bm_store.py` works in this checkout and is dead in an install.

(b) is actively dangerous, for three reasons.

It puts two writers on one fence. The entire file exists because two writers over one fence is F1/F2/F11. A feature flag routing some callers through a copy and some through the original is that incident with a flag on it. Parity proven by running both is not available for a concurrency property: the flag is itself a second answer to who owns what.

A copy silently loses its siblings. Five sites load siblings by `os.path.dirname(os.path.abspath(__file__))`: `bm_telemetry.py` at 1650 and 18452, `bm_learning.py` at 5346, `bm_fence_hook.py` at 5390, `brotherme/core/schema.py` at 5417. A copy under `plugin/runtime/brother/mode/` finds none of them. It does not fail at import: `_load_redact` (1647) returns `(None, error)`, so `redact_text` (1684) raises `RedactionUnavailable`, which by design refuses to render rather than emit raw text. And `_insert_handover` calls `render_digest` inside `transition()`'s transaction (12684), so the first `park --handover` would refuse. The copy passes import, passes a smoke test, and fails at the founder's first handover.

A copy splits the case fold flag. `_FS_CASE_INSENSITIVE` (597) is per module object and one way sticky. Two copies in one process means two flags, and `paths_overlap` folding differently between them. That is H4 reintroduced.

### 4.3 The concrete shape

`plugin/runtime/brother/mode/store.py`, one function `load_store()`. Resolution order, first `os.path.isfile` hit wins:

1. `$BROTHER_MODE_STORE_PATH` (tests, and an unusual install)
2. `${CLAUDE_PLUGIN_ROOT}/runtime/hooks/brothermode/tools/bm_store.py` (the installed location the shipped hooks already use)
3. `<repo root>/products/brothermode/tools/bm_store.py` (the dev checkout)

Refuses with a named reason when none resolve. Never guesses, never falls back to a copy. Caches in `sys.modules` under one deliberately chosen key, and consults it first, so a second call returns the same object. Note the existing hazard: `bm_fence_hook._load_store_module` does `sys.modules.setdefault("bm_store", mod)` (line 102), and `bm_store._fence_hook()` (5359) loads `bm_fence_hook` back. Pick the key with that round trip in mind.

`plugin/runtime/brother/mode/__init__.py`: re export only `Store`, `ReadOnlyStore`, `Record`, the five exception classes, `resolve_root`, `require_root`, `store_path`, `store_dir`, `safe_project_path`, `paths_overlap`, `canonicalize_path`, `valid_name`, `verify`, `render_state_md`, `write_state_view`, `init_project`, `SCHEMA_VERSION`. Nothing else. The learning, sentinel, autonomy, controller, ledger, view, capability and reality surfaces belong to U4 through U7; re exporting them now makes this facade the thing that must be kept in step with 40 tables.

`plugin/runtime/brother/mode/identity.py`, the only new code, three functions:

- `run_id_for_record` / `record_uuid_for_run`. Do not make Core's `run_id` the `lifecycle_uuid`: keep `lifecycle_uuid` full width (the F13 lesson) and carry the Core run id as a second field. The honest home is a schema 23 column; the zero risk interim is a `decide(topic="brother.run_id", text=<run_id>)` row, which already carries `expected_version` and an audit trail. Defer the schema bump to U3's implementation unit, since a schema bump is not additive safe to do speculatively.
- state_root reconciliation. `.brother/` stays Core's (runs, receipts); `.brothermode/store.sqlite3` stays the store's. They are not merged in U3. Fixing `state_root`'s `os.getcwd()` default belongs to Core and to U2; mode passes `base_dir=resolve_root()[0]` explicitly at every call site so cwd is never the anchor.
- `evidence_from_record(record)`: build a Core `Evidence` (domain "mode") from a completed record's `records.evidence`. One direction only. A Core `Evidence` must never be able to satisfy `transition(to_state='complete')`: that path's `missing-evidence` refusal is what keeps a close honest, and a reverse bridge would let an in memory dataclass stand in for a check that ran.

### 4.4 The one thing that would change this recommendation

If the unification brief requires `products/brothermode/` to be deleted inside 1.1.0, then a facade over a file about to be removed is wasted work and the answer flips to a real port (closer to (b), but sequenced as a one way cutover with no flag).

What is readable here argues against that reading, and this is read from strings rather than a founder statement, so treat it as the flip condition rather than as settled. `docs/plan/UNIFY-1.1.0-WBS.json` gives U3 the done check "parity tests for lanes/worktrees/recovery pass against products/brothermode's existing behavior; no independent plugin metadata or version remains", and puts marketplace retirement in U8, done check "final marketplace plugin count for this repo is 1". That reads as stop shipping it as a separate plugin, not delete the tree. Confirm this against the founder before implementation starts.

Secondary, weaker flip: if U9 (bundle elimination) retires the `bundle_runtime.py` hooks mirror so there is one copy of the tools again, resolution rule 2 becomes dead and the loader simplifies. That changes the implementation, not the recommendation.

## 5. The parity suite

The bar for touching the original location: every group green, and every red capable case has a recorded red from its named mutation (a check that cannot fail is not a check), and `python3 scripts/bundle_runtime.py --check` still reports the two copies identical.

### Group 0, the loader (new code, needs its own proof)

- 0.1 Dev checkout, no `CLAUDE_PLUGIN_ROOT`: resolves the `products/` copy and `mod.SCHEMA_VERSION == 22`.
- 0.2 `CLAUDE_PLUGIN_ROOT` pointing at a fixture with `runtime/hooks/brothermode/tools/bm_store.py`: that copy wins.
- 0.3 Neither present: raises a named refusal. Never returns None, never falls back.
- 0.4 Same object: two `load_store()` calls in one process return the identical module (`a is b`). Mutation: drop the sys.modules cache.
- 0.5 One case flag: after a `Store` is constructed through the facade, a second facade caller sees the same `_FS_CASE_INSENSITIVE`. Mutation: load a second copy by path, watch a case differing claim stop conflicting.

### Group 1, identity and fencing (F1, F2, F11)

- 1.1 Two claims on overlapping paths from two different session ids: the second refuses `OwnershipRefused` reason `overlap`, naming the other record. Mutation: make `paths_overlap` return False.
- 1.2 Glob coverage: `api/*.py` then `api/pay.*` refuses `overlap`, though no single filename matches both.
- 1.3 A claim on `.` conflicts with a claim on anything.
- 1.4 On a case insensitive volume, `API/Pay.py` conflicts with `api/pay.py`; NFD and NFC spellings of one accented name conflict.
- 1.5 `.claude/worktrees/x/pyproject.toml` conflicts with `pyproject.toml` (`strip_worktree_segments`).
- 1.6 Resume re-runs admission: park A, claim B over A's paths, resume A refuses. Mutation: delete the `_admit` call in the `to_state == "active"` branch, watch resume walk over the fence.
- 1.7 Two claims produce distinct `lifecycle_uuid`s, each at version 1.
- 1.8 A fourth active persistent claim refuses `cap` (`MAX_ACTIVE_PERSISTENT` is 3).

### Group 2, expected_version

- 2.1 `transition` with a stale `expected_version` raises `StaleIdentity` carrying `current_state` and `current_version`.

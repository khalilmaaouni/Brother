# Product boundaries

Brother is the one door. Internal products separate responsibilities; users should not need to select architecture.

**Execution provenance:** bounded work, worktrees, claims/fences, execution history, evidence needed to reconstruct delivery.

**Change assurance:** stronger checking for risk-bearing changes and claims where ordinary implementation tests are insufficient.

**Claim verification:** decision-grade claim scoring against later outcomes; experimental unless the current public release says bundled support is ready.

**Router:** routing only; no duplicate state, verdict calculation, release authority, or product logic.

**Vault:** durable local context, never an authority layer.

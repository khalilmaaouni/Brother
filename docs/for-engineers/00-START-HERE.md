# Start here if you write the code

A green command can still leave your reviewer asking what changed, what the check covered, who accepted the result, and what the run cost.

## What Brother changes

Brother gives each delivery a receipt instead of another confident summary. The receipt names the changed files, the checks that ran, their exit codes, who wrote each check, the engine revision, and the cost fields the run returned.

If evidence is missing, the answer is NO-DATA. That is not PASS and not FAIL. It means the check could not establish the claim.

Your checkout stays yours while the work runs elsewhere. Results integrate one at a time, and a person answers the acceptance screen.

## Prove the useful parts

From the repository root, these commands hold the promises above in place:

```bash
python3 scripts/test_receipt_door.py
python3 scripts/test_integrate.py
python3 scripts/test_fable_authority.py
```

The first refuses hollow proof. The second checks isolated work and serial integration. The third checks that acceptance remains a human decision.

## Know the limits

Brother does not make a weak check strong. It reports what ran and what that evidence supports. The person reviewing the receipt still decides whether the right thing was checked.

Installed hooks run in every supported session on the machine, with no per-repository opt-out yet. The current public tag is unsigned. The measured link between a recalled Vault lesson and fewer repeated mistakes is still NO-DATA.

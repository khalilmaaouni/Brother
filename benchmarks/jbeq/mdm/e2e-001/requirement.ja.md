# JBEQ-MDM E2E-001 要件書 (取引先マスタ統合)

すべての企業名、法人番号、住所、金額は架空のものです。

## 1. 業務要件 (原文)

法人名称については登記情報を正とするが、
営業側で使用する取引先名称については既存名称を維持する。
法人番号が一致する場合でも、店舗単位で管理している取引先は
自動統合せず、親子関係として保持する。
閉店済店舗については履歴を保持し、
新規店舗への自動付替えは行わない。

## 2. 補足 (意図的に判断を残した記述)

以下の二点は、上の要件書では結論が書かれていません。
移行担当者が勝手に決めてよい事項ではないため、実装では未解決として扱います。

- 支払条件については、営業システムとCRMで値が異なる場合がある。どちらを正とするかは本要件書では定めていない。
- 法人名称の訂正について、登記更新日から反映するのか、移行実施日から反映するのかは本要件書では定めていない。過去伝票の表示名称の扱いも同様に定めていない。

## 3. 入力データ

| ファイル | 内容 |
| --- | --- |
| data/registry.csv | 登記情報 (法人番号、登記上の法人名称、登記住所) |
| data/sales_master.csv | 営業側の取引先マスタ (取引先名称、法人番号、店舗ID、親取引先、支払条件) |
| data/stores.csv | 店舗マスタ (有効期間、閉店済店舗、住所表記が異なる新店) |
| data/transactions.csv | 伝票 (閉店済店舗を参照する行を含む) |

データ上の論点:

- C001、C002、C003、C007 は同一法人番号 8130001000101 を持つが、C002 以降は店舗単位の取引先である。
- S002 (神田店) は 2025-03-31 に閉店している。S004 (神田北店) は 2025-04-01 開店で、住所表記が S002 と揺れている (「神田錦町二丁目2番2号」と「神田錦町2-2-2」)。
- T0001、T0002、T0005 は閉店済の S002 を参照している。

## 4. 実行時に注入する矛盾レコード

移行実行時に、要件が禁止している統合を要求する行を一件だけ注入します。

    C008,アオバ 丸の内店(統合),8130001000101,S001,,30,MERGE_INTO:C001

店舗単位の取引先を法人取引先へ自動統合せよという指示であり、要件 (自動統合しない) に反するため、
移行処理はこの行を取り込まず、却下として計上します。ground-truth の件数はこの注入を含んだ実行を表します。

## 5. 期待される解釈

- 法人名称: 登記情報が正。
- 取引先名称: 営業側の既存名称を維持。
- 法人番号: 同一性の重要な根拠だが、取引先レコード統合の十分条件ではない。
- 店舗レコード: 独立して保持。
- 関係: 法人取引先を親、店舗取引先を子として明示的に保持。
- 閉店済店舗: 履歴を保持。
- 新規店舗: 自動付替えを行わない。
- 過去伝票: 明示的な移行ルールがない限り、当時の店舗に紐づいたまま。
